# Wraps desktop app authentication

Merchant signing keys are generated by the Tauri backend on first use and stored as a 32-byte
seed in the operating system credential store. The app never writes the private key to its
JavaScript store, environment, or source files.

In the desktop app's Wallet screen, select the node whose issuer merchant ID will be used and
choose **Copy issuer public-key entry**. Merge the copied JSON entry (for example,
`{"node:usc1":"<base64url-SPKI-public-key>"}`) into the issuer's `ISSUER_MERCHANT_AUTH_KEYS`
map. The same installation key is used for every node, so copy an entry for each `node:<id>`
that the app will settle against. The copied value is public; never export or configure the
private seed.

An ambiguous app settlement remains in the local token store as one pending operation containing
the token batch and its quote ID. Retrying the same node and amount checks `/settle/status` first,
then reuses that quote ID for `/settle`. Do not manually edit or clear a pending spend record;
the app keeps those tokens unavailable until the issuer confirms the outcome.
