# Research notes for Wraps

This is a curated reading list for Wraps, a private payment system for agents using a relay and confidential computing. It contains 55 papers and concise findings, with practical implications. Findings summarize the papers' stated results; implications are engineering interpretations, not claims that the papers evaluated Wraps. The list spans peer-reviewed work and clearly linked preprints because several emerging agent-payment protocols have not yet accumulated a mature peer-reviewed literature. Check publication versions before relying on a result for a security decision.

## Main themes for the design

- Bind every authorization to the recipient, asset, amount, purpose, expiry, and one-time transaction context; verify those bindings at execution and settlement. Valid signatures alone do not prove that the executed purchase still matches user intent.
- Treat relays as metadata observers even when payloads are encrypted. Timing, packet sizes, retries, DNS, IP addresses, and public ledger events can enable linkage.
- Attestation must cryptographically bind the measured workload to the key that terminates the authenticated channel. A valid quote beside an unrelated TLS session is insufficient.
- Confidential computing reduces trust in the host, but does not remove side channels, rollback, availability failures, or application bugs. Keep secrets and trusted code minimal; test operational failure paths.
- Agent policy belongs in deterministic authorization and payment code, not solely in model instructions. Treat retrieved content and tool output as untrusted, and require independent enforcement before spending.
- Measure privacy, latency, bandwidth, liquidity, and cost together. Batching and cover traffic can improve anonymity while increasing delay or resource use.

## Agent and payment-protocol security

1. **When HTTP 402 Meets the Blockchain: Risks on Emerging x402 Payments** (USENIX Security 2026). [Paper](https://www.usenix.org/conference/usenixsecurity26/presentation/wang-qinying). Studies x402 facilitators and transactions, derives eight security rules, and reports violations across evaluated facilitators plus attacks involving free service, asset theft, denial of service, and gas abuse. **Wraps:** independently validate facilitator payment requirements and bind payment to the exact resource and fulfillment.
2. **SoK: Security of Autonomous LLM Agents in Agentic Commerce** (2026 preprint). [arXiv](https://arxiv.org/abs/2604.15367). Organizes agent-commerce risk into agent integrity, transaction authorization, inter-agent trust, market manipulation, and compliance, with cross-layer attack chains. **Wraps:** review model, tool, authorization, custody, and settlement boundaries as one lifecycle.
3. **A Formal Analysis of Agent Payment Protocols** (2026 preprint). [arXiv](https://arxiv.org/abs/2609.00060). Models x402, MPP, ACP, and AP2 in Tamarin and reports missing bindings and state constraints across protocol stages. **Wraps:** formalize invariants connecting user intent to resource, payment, and fulfillment; treat this as a recent preprint requiring independent review.
4. **Zero-Trust Runtime Verification for Agentic Payment Protocols** (2026 preprint). [arXiv](https://arxiv.org/abs/2602.06345). Identifies replay and context-redirect risks in mandate use and proposes execution-time context binding with consume-once nonces. **Wraps:** retries need idempotency and explicit consume-once semantics, not just signed requests.
5. **Beyond the Mandate: A Systematic Security Analysis of the Agent Payments Protocol (AP2)** (2026 preprint). [arXiv](https://arxiv.org/abs/2608.23858). Argues signed mandates do not protect the pre-authorization context from manipulation through agent interactions and tools. **Wraps:** authorization UI/policy should show and sign the final normalized transaction after untrusted inputs are incorporated.
6. **AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents** (2024). [arXiv](https://arxiv.org/abs/2406.13352). Provides 97 tasks and 629 security tests; finds agents fail useful tasks and injections break some security properties despite defenses. **Wraps:** test payment agents with hostile merchant pages and tool output, measuring both task utility and unauthorized actions.
7. **Formalizing and Benchmarking Prompt Injection Attacks and Defenses** (USENIX Security 2024). [Paper](https://www.usenix.org/conference/usenixsecurity24/presentation/liu-yupei). Formalizes injection attack classes and evaluates five attacks and ten defenses across models and tasks. **Wraps:** threat-model indirect instructions from merchant metadata, receipts, and relay responses.
8. **StruQ: Defending Against Prompt Injection with Structured Queries** (USENIX Security 2025). [Paper](https://www.usenix.org/conference/usenixsecurity25/presentation/chen-sizhe). Separates instructions from untrusted data and uses a specially trained model/interface to reduce instruction confusion. **Wraps:** preserve structured separation in prompts, while retaining deterministic payment checks because model-level separation is not an authorization boundary.
9. **Simple Prompt Injection Attacks Can Leak Personal Data Observed by LLM Agents During Task Execution** (2025 preprint). [arXiv](https://arxiv.org/abs/2506.01055). Shows data-flow prompt injections can exfiltrate personal information from agent workflows, with attack success varying by task and defenses. **Wraps:** minimize sensitive context exposed to merchant-facing tools and restrict outbound data channels.
10. **Assessing Automated Prompt Injection Attacks in Agentic Environments** (2026 preprint). [arXiv](https://arxiv.org/abs/2606.10525). Evaluates automated prompt injection against AgentDojo and finds black-box optimization can outperform gradient-based attacks, with transfer and success dependent on attacker model. **Wraps:** do not assume static injection filters cover adaptive attackers.
11. **AgentDyn: A Dynamic Open-Ended Benchmark for Evaluating Prompt Injection Attacks** (2026 preprint). [arXiv](https://arxiv.org/abs/2602.03117). Introduces open-ended shopping and web tasks; reports current defenses can be insecure or over-restrictive. **Wraps:** test realistic purchases and useful behavior, not only fixed attack strings.
12. **MUZZLE: Adaptive Agentic Red-Teaming of Web Agents Against Indirect Prompt Injection Attacks** (USENIX Security 2026). [Paper](https://www.usenix.org/conference/usenixsecurity26/presentation/syros). Uses adaptive red-teaming and reports new attacks across web applications, models, and agent scaffolds. **Wraps:** include adaptive merchant/content attacks in security review and regression suites.
13. **How to Bind Anonymous Credentials to Humans** (USENIX Security 2023). [Paper](https://www.usenix.org/system/files/usenixsecurity23-hesse.pdf). Examines the challenge of tying privacy-preserving credentials to people without undermining their privacy properties. **Wraps:** be explicit about whether Wraps proves a wallet, agent, or human identity; avoid implying stronger identity guarantees.
14. **Personhood Credentials: Artificial Intelligence and the Value of Privacy-Preserving Tools to Distinguish Who Is Real Online** (2024 preprint). [arXiv](https://arxiv.org/abs/2408.07892). Discusses privacy-preserving ways to establish personhood and the governance and misuse risks around credentials. **Wraps:** minimize identity disclosure and document who can correlate credential issuance and use.

## Payment privacy, credentials, and e-cash

15. **Token-Based Payment Systems** (2022 preprint). [arXiv](https://arxiv.org/abs/2207.07530). Develops a taxonomy of token-payment architectures, roles, and privacy/accountability choices. **Wraps:** use the taxonomy to state precisely which parties learn issuance, spend, and settlement metadata.
16. **Privacy-Enhancing Technologies for Digital Payments: Mapping the Landscape** (BIS Working Paper 1242, 2025). [BIS](https://www.bis.org/publications/working-paper-1242-privacy-enhancing-technologies-digital-payments-mapping-landscape). Maps techniques including zero-knowledge proofs, homomorphic encryption, MPC, anonymous signatures, and TEEs, highlighting privacy, auditability, and performance tradeoffs. **Wraps:** select techniques against specific observers and compliance needs rather than treating “privacy” as one property.
17. **A Hitchhiker’s Guide to Privacy-Preserving Digital Payment Systems: A Survey on Anonymity, Confidentiality, and Auditability** (2025 preprint). [arXiv](https://arxiv.org/abs/2505.21008). Surveys privacy goals, construction families, and open tension between anonymity and auditability. **Wraps:** define threat models and what authorized dispute resolution can reveal.
18. **Privacy and Cryptocurrencies – A Systematic Literature Review** (IEEE Access 2020). [DOI](https://doi.org/10.1109/ACCESS.2020.2980950). Reviews cryptocurrency privacy mechanisms and recurring weaknesses, including metadata and implementation-level leakage. **Wraps:** audit information flows beyond cryptographic transaction fields.
19. **Anonymity on Blockchain-Based E-Cash Protocols—A Survey** (Computer Science Review 2021). [DOI](https://doi.org/10.1016/j.cosrev.2021.100394). Surveys anonymity mechanisms and deanonymization threats in blockchain e-cash. **Wraps:** evaluate linking attacks across wallet behavior, network observation, and public chain data.
20. **Zerocash: Decentralized Anonymous Payments from Bitcoin** (IEEE S&P 2014). [Paper](https://doi.org/10.1109/SP.2014.36). Introduces zero-knowledge shielded payments hiding transaction values and addresses while maintaining public ledger validity. **Wraps:** a useful reference for separating ledger verification from disclosure of transaction details.
21. **Coconut: Threshold Issuance Selective Disclosure Credentials with Applications to Distributed Ledgers** (ACM CCS 2018). [arXiv](https://arxiv.org/abs/1802.07344). Combines threshold issuance, re-randomizable credentials, and selective disclosure to support unlinkable proofs. **Wraps:** relevant design pattern if issuer trust should be distributed and credentials selectively revealed.
22. **Compact and Divisible E-Cash with Threshold Issuance** (2023 preprint). [arXiv](https://arxiv.org/abs/2303.08221). Studies divisible e-cash with decentralized issuance and reports tradeoffs between compact payment representations and deposit cost. **Wraps:** useful if future work needs private variable-denomination balances; measure settlement complexity.
23. **Blind Signatures for Untraceable Payments** (CRYPTO 1982). [DOI](https://doi.org/10.1007/978-1-4757-0602-4_18). Introduces blind signatures as a way for a bank to issue electronic cash without learning which later spend corresponds to issuance. **Wraps:** issuance/redemption unlinkability is a concrete privacy property, but double-spend prevention and redemption metadata need separate treatment.
24. **Provably Unlinkable Smart Card-Based Payments** (ACM CCS 2023). [Proceedings](https://sigsac.hosting.acm.org/ccs/CCS2023/tocs/tocs-ccs23.html). Presents UTX, a privacy-oriented EMV-style protocol, and formally analyzes security/privacy properties. **Wraps:** payment usability and privacy properties can be jointly specified and formally checked.
25. **DEMO: Privacy-Preserving Payments** (SIGCOMM 2025). [DOI](https://doi.org/10.1145/3744969.3748416). Demonstrates token e-cash with blind-signature issuance/redemption unlinkability and discusses recipient identification and amount-related costs. **Wraps:** document where unlinkability ends, especially redemption, merchant, and refund flows.
26. **A Digital Currency Architecture for Privacy and Owner-Custodianship** (2021 preprint). [arXiv](https://arxiv.org/abs/2101.05259). Explores privacy-enhancing token and proof mechanisms in a digital-currency architecture. **Wraps:** useful architecture vocabulary for custody boundaries and selective visibility.
27. **SoK: Auditability and Accountability in Distributed Payment Systems** (IACR ePrint 2021/239). [IACR](https://eprint.iacr.org/2021/239). Surveys auditability models and identifies gaps involving disputes and off-chain state. **Wraps:** preserve enough verifiable evidence to resolve payment disputes without logging unnecessary personal data.
28. **Twilight: A Differentially Private Payment Channel Network** (USENIX Security 2022). [Paper](https://www.usenix.org/conference/usenixsecurity22/presentation/dotan). Applies differential privacy to hide payment-channel liquidity information and analyzes privacy/cost tradeoffs. **Wraps:** relays and liquidity checks can leak behavior even if individual payments are off-chain.
29. **Remote Side-Channel Attacks on Anonymous Transactions** (USENIX Security 2020). [Paper](https://www.usenix.org/conference/usenixsecurity20/presentation/tramer). Demonstrates remote side-channel attacks that weaken privacy claims of shielded cryptocurrency systems. **Wraps:** cryptographic anonymity must be paired with implementation and resource-usage analysis.
30. **A Fistful of Bitcoins: Characterizing Payments Among Men with No Names** (2013). [USENIX login](https://www.usenix.org/publications/login/december-2013-volume-38-number-6/fistful-bitcoins-characterizing-payments-among). Shows address-clustering heuristics can associate a significant portion of Bitcoin activity with entities. **Wraps:** pseudonymous addresses and fresh keys alone do not guarantee untraceability.

## Relays, network privacy, and traffic analysis

31. **The Loopix Anonymity System** (2017). [arXiv](https://arxiv.org/abs/1703.00536). Combines Poisson mixes, cover traffic, and delays to provide sender/receiver anonymity under its stated adversary model. **Wraps:** cover traffic can protect relay users, but introduces measurable latency and bandwidth costs.
32. **Anonymity Mixes as (Partial) Assembly Queues: Modeling and Analysis** (2019). [arXiv](https://arxiv.org/abs/1907.11603). Models batching and delay, showing the privacy/latency balance depends on queue and batch policy. **Wraps:** tune batching from measured workload and state the resulting latency/privacy tradeoff.
33. **Studying the Anonymity Trilemma with a Discrete-Event Mix Network Simulator** (2021). [arXiv](https://arxiv.org/abs/2107.12172). Simulates the tension among anonymity, latency, and bandwidth in mix networks. **Wraps:** use simulation to size relay cover traffic and batch parameters before deployment.
34. **k-Fingerprinting: A Robust Scalable Website Fingerprinting Technique** (USENIX Security 2016). [Paper](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/hayes). Shows classifiers can identify visited sites from encrypted traffic patterns at useful accuracy. **Wraps:** encryption does not hide destination or usage patterns from a traffic observer.
35. **Effective Attacks and Provable Defenses for Website Fingerprinting** (USENIX Security 2014). [Paper](https://www.usenix.org/conference/usenixsecurity14/technical-sessions/presentation/wang_tao). Studies packet-sequence analysis and defenses for identifying web activity over Tor. **Wraps:** pad or shape traffic only with a measured threat model and overhead budget.
36. **Zero-Delay Lightweight Defenses Against Website Fingerprinting** (USENIX Security 2020). [Paper](https://www.usenix.org/conference/usenixsecurity20/presentation/gong). Evaluates lightweight dummy-packet defenses that target fingerprinting without adding latency, at bandwidth cost. **Wraps:** bandwidth padding may be a practical privacy option where delay is unacceptable.
37. **Subverting Website Fingerprinting Defenses with Robust Traffic Representation** (USENIX Security 2023). [Paper](https://www.usenix.org/system/files/usenixsecurity23-shen-meng.pdf). Finds robust traffic representations can identify sites despite several existing defenses. **Wraps:** avoid claims of traffic-analysis resistance based only on payload encryption or simple padding.
38. **Robust Website Fingerprinting Through the Cache Occupancy Channel** (USENIX Security 2019). [Paper](https://www.usenix.org/system/files/sec19-shusterman.pdf). Demonstrates a cache side channel for website fingerprinting and explores cache activity as mitigation. **Wraps:** local and shared-compute side channels may remain outside the relay protocol’s encryption guarantees.
39. **The Effect of DNS on Tor’s Anonymity** (NDSS 2017). [Paper](https://www.ndss-symposium.org/ndss2017/ndss-2017-programme/e-effect-dns-tors-anonymity/). Analyzes how DNS handling can expose activity and enable correlation in an anonymity network. **Wraps:** route DNS through the protected path and test leak behavior on failures.
40. **Online Website Fingerprinting: Evaluating Website Fingerprinting Attacks on Tor in the Real World** (USENIX Security 2022). [Paper](https://www.usenix.org/system/files/sec22-cherubin.pdf). Evaluates fingerprinting under realistic online conditions, showing operational conditions affect attacker success. **Wraps:** test relay privacy against realistic concurrent traffic and changing network conditions.
41. **VPNInspector: Systematic Investigation of the VPN Ecosystem** (NDSS 2022). [Paper](https://www.ndss-symposium.org/ndss-paper/auto-draft-244/). Studies commercial VPN clients and identifies security/privacy failures including DNS/IPv6 leaks and tunnel-failure behavior. **Wraps:** verify kill-switch, DNS, IPv6, and reconnect behavior; a VPN tunnel alone is not an anonymity guarantee.
42. **Raptor: Routing Attacks on Privacy in Tor** (USENIX Security 2015). [Proceedings](https://www.usenix.org/sites/default/files/sec15_full_proceedings_interior.pdf). Shows autonomous-system routing asymmetry and timing observation can enable deanonymization. **Wraps:** network-path adversaries may correlate traffic outside the relay operator’s control.
43. **Encrypted DNS → Privacy? A Traffic Analysis Perspective** (NDSS). [Paper](https://www.ndss-symposium.org/ndss-paper/encrypted-dns-privacy-a-traffic-analysis-perspective/). Studies how encrypted DNS traffic patterns can still reveal information through analysis. **Wraps:** encrypted DNS protects query contents but may not hide timing, resolver, or access patterns.
44. **Ryoan: A Distributed Sandbox for Untrusted Computation on Secret Data** (OSDI 2016). [Paper](https://www.usenix.org/sites/default/files/osdi16_full_proceedings.pdf). Describes a TEE-based sandbox for safely composing untrusted modules over secret inputs, with an explicit threat model. **Wraps:** isolate third-party code and keep its data access narrow; sandboxing still requires side-channel and availability analysis.

## Confidential computing and attestation

45. **Separate but Together: Integrating Remote Attestation into TLS** (USENIX ATC 2025). [Paper](https://www.usenix.org/conference/atc25/presentation/weinhold). Presents a way to combine TLS identity and remote-attestation assurances while ensuring the channel terminates at the attested endpoint. **Wraps:** bind the relay’s attested public key into the actual TLS channel and verify it before sending payment data.
46. **Transparent Attested DNS for Confidential Computing Services** (USENIX Security 2025). [Paper](https://www.usenix.org/conference/usenixsecurity25/presentation/delignat-lavaud). Proposes public, policy-checked attestation records that bind confidential services to domain names and certificates. **Wraps:** attestation discovery and policy transparency can reduce bespoke client trust configuration.
47. **MAGE: Mutual Attestation for a Group of Enclaves without Trusted Third Parties** (USENIX Security 2022). [Paper](https://www.usenix.org/conference/usenixsecurity22/presentation/chen-guoxing). Enables a group of enclaves to mutually attest without a separate trusted third party. **Wraps:** relevant if multiple confidential components need to establish trust directly; assess complexity against a single verifier.
48. **Remote Attestation of SEV-SNP Confidential VMs Using e-vTPMs** (2023 preprint). [arXiv](https://arxiv.org/abs/2303.16463). Explores ephemeral virtual TPMs for attesting SEV-SNP VMs without persistent host state. **Wraps:** useful background for stateless VM identity and key provisioning in confidential space.
49. **Confidential Attestation: Efficient In-Enclave Verification of Privacy Policy Compliance** (2020 preprint). [arXiv](https://arxiv.org/abs/2007.10513). Moves policy analysis into proof/evidence generation so remote verification can remain comparatively small. **Wraps:** separate policy evaluation from trust in a large verifier where practical.
50. **Varys: Protecting SGX Enclaves from Practical Side-Channel Attacks** (USENIX ATC 2018). [Paper](https://www.usenix.org/conference/atc18/presentation/oleksenko). Proposes a system to reduce practical SGX side-channel leakage and evaluates its overhead. **Wraps:** enclave execution does not automatically conceal access patterns; review side-channel exposure and mitigations.
51. **Foreshadow: Extracting the Keys to the Intel SGX Kingdom with Transient Out-of-Order Execution** (USENIX Security 2018). [Paper](https://www.usenix.org/conference/usenixsecurity18/presentation/bulck). Demonstrates attacks extracting enclave secrets and forging attestation under vulnerable hardware conditions. **Wraps:** attestation policy must account for platform security advisories, TCB version, and revocation.
52. **ScaRR: Scalable Runtime Remote Attestation for Complex Systems** (RAID 2019). [Paper](https://www.usenix.org/conference/raid2019/presentation/toffalini). Studies scalable runtime attestation for complex systems beyond a single static binary measurement. **Wraps:** define which runtime components and updates the verifier actually needs to trust.
53. **Semantic Remote Attestation** (USENIX VM 2004). [Paper](https://www.usenix.org/legacy/event/vm04/tech/haldar/haldar_html/). Explains that measuring a binary is only indirect evidence of policy-compliant behavior and proposes semantic attestation. **Wraps:** verify measured code, configuration, and policy assumptions; a hash does not prove business correctness.
54. **Turtles All The Way Down: Research Challenges in User-Based Attestation** (USENIX HotSec 2007). [Paper](https://www.usenix.org/legacy/events/hotsec07/tech/full_papers/mccune/mccune_html/). Discusses limitations of attesting software state, including the gap between platform evidence and the user's intended trust relationship. **Wraps:** explain attestation claims in terms a payer can understand and avoid treating them as a blanket guarantee.
55. **On the Atomicity and Efficiency of Blockchain Payment Channels** (USENIX Security 2025). [Paper](https://www.usenix.org/conference/usenixsecurity25/presentation/wu-di). Formalizes state ambiguity in payment-channel transitions and proposes a resolve mechanism with a Universal Composability security argument. **Wraps:** model retries, concurrent settlement, and conflicting outcomes explicitly; a payment should have one unambiguous final state.
56. **High Throughput Cryptocurrency Routing in Payment Channel Networks** (NSDI 2020). [Paper](https://www.usenix.org/system/files/nsdi20-paper-sivaraman.pdf). Introduces Spider, which splits payments across paths to address liquidity imbalance and improve payment-channel throughput. **Wraps:** relay liquidity and routing strategy can dominate performance even when cryptography is fast.
